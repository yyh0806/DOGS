# M2.1 验收记录 — 园区基准点 + 双目标规划 (feature/brain-m2p1-campus-loop)

日期: 2026-08-31 · 基座: v1.0.0-alpha.2 · 目标 tag: v1.0.0-alpha.2.1

## 需求 (用户原话)

> 不要按照蠡湖的来，按照 120.369486, 31.488192 这个经纬度（无锡太科园
> 园区, 园区里面有湖），无论我说绕湖还是绕园区应该都能生成航线才是。

## 交付

1. **基准点切换**: golden 夹具从蠡湖换到太科园园区坐标
   (31.488192, 120.369486); MockAdapter 默认 GPS 同步切换。
2. **感知缺陷修复**: 旧阶梯 z13 起步 + 候选只扫面积前 8 → 园区内小湖
   被挤出候选, "绕湖"选到 11km 外的大湖。改为**先近后远**
   (z16→z14→z12) + 候选扫描前 24 → 园区 100m 处景观塘被正确选中。
3. **绕园区目标 (kind=campus)**: `osm_client.py` 新增 Overpass 向量
   获取 (镜像轮换 + 缓存 + 离线开关); 园区 = 中心所在 landuse 地块按
   同类邻近泛洪聚类 → 凸包外轮廓 → 复用离岸外扩管线; **矢量级保证**
   环线任何点不落入凸包内 (角部切入径向推出后处理)。
4. **新工具** `plan_campus_loop` (read 级, 摘要+plan_store 引用传递);
   plan_lake_loop 描述明确"最近合格水体"语义, LLM 按任务词义选工具。
5. 输出契约统一: `target` 字段 (kind/centroid/area/perim/dist),
   `water_polygon` | `campus_polygon`。

## 过程中发现并修复的问题

1. `plan_route(kind=water)` 旧阶梯选湖选到 11km 外 (见上) —— 需求
   本身暴露的真缺陷;
2. 园区缩放选择误用瓦片细化的 `nx>=2` 条件, 小园区全缩放被拒
   (campus_too_large) —— 纯向量规划无瓦片约束, 改为像素跨度 300~3600px;
3. 凸包角部 chaikin 圆角切入 ~5m —— 加矢量级推出后处理 + 零入包测试;
4. **plan 工具 `kind=` 关键字与 SessionLog.append 首参冲突** (TypeError):
   LLM 演示撞出, 且正确拒绝编造航点继续 (安全架构生效); 修复 + 测试
   哑日志改为同签名防再犯;
5. 多测试目录 `import conftest` 歧义解析 → 测试文件自含常量;
6. brain/lake_plan 两套测试环境变量路径不一致互相污染 → 统一 fixtures/cache。

## 已知限制

- 园区聚类在基准点为单地块 (OSM 邻近地块非同类/间距大); 聚类半径与
  间隙是参数 (campus_radius_m / cluster_gap_m), 整片园区轮廓依赖 OSM
  数据质量;
- Overpass 三个镜像均不稳 (主站 504), 已做轮换重试 + 强缓存。
